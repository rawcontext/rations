6fWhat Liquid Glass changed here, and what it deliberately didn’t
Where the glass goes. Apple’s guidance reserves Liquid Glass for the layer that floats above content: menus, popovers, alerts, toolbars. So the menu, the submenu, the switch panel and the alert are glass; the Settings form and its groups are not. No glass on glass.
macOS 27 refinements applied. Golden Gate made the material a little more opaque so it diffuses busy wallpaper, and added a darkened edge with a brighter specular rim for separation; both are in the panel edges here. Window corners share one, less dramatic radius (12pt). The menu bar itself is transparent since Tahoe, so the status item sits directly on the wallpaper with a subtle shadow for contrast, and its pressed state is a glass pill. Users can now dial glass from clear to tinted in System Settings › Appearance; the design has to read at both ends, so text never relies on the material for contrast.
Menu. Items are 24pt with a 7pt-radius highlight in the accent color, separators are inset, and the menu corners are 12pt. Menu-item icons are optional per the HIG (“not all menu items need an icon”), and the account rows already carry a lot of information, so none were added.
Controls. Pop-up buttons, segmented controls, steppers and push buttons take the capsule shapes of the new design; Cancel uses the translucent glass style, Try Again the prominent tinted one. Toggles are unchanged.
Settings. A tabbed toolbar (General · Accounts · Providers) with a grouped form, the standard shape for a small Mac app’s Settings scene. Accounts is new: saved Codex sign-ins with the signed-in one marked, add and remove, rename in place. The three tab glyphs are placeholders for SF Symbols (slider.horizontal.3, person.fill, square.grid.2x2).
Sources. Apple HIG › Materials and “Meet Liquid Glass” (WWDC25); WWDC26 Golden Gate design notes as reported by MacRumors, Macworld and AppleInsider (opacity, edge, corner radius, transparency slider, single-window menu bar with overflow).

5dAnswers and how switching works
“Open Dashboard” was PRD FR-11: one link per provider that opens the vendor’s own usage page in your browser (for Codex, the usage page on chatgpt.com). Nothing embedded. Renamed to say where it goes.
The ↺ glyph is not a button. It is the same symbol as the ↺ column: reset-credit inventory the vendor reports. Rations only reads it; redeeming happens inside Codex. The submenu now says “2 reset credits · redeem in Codex” or “No reset credits”.
Switching accounts. Codex keeps the active sign-in in one file, ~/.codex/auth.json. Every open-source switcher works by saving a copy of that file per account and swapping it: liuzhao1225/codex-account-switcher (native Swift menu bar app, macOS 14+), Lampese/codex-switcher, denysdovhan/codex-account, Sls0n/codex-account-switcher, MinhVuong1997/codex-profiles-bar.
The sequence shown in 5b follows codex-account-switcher’s SwitchService: quit Codex Desktop (a normal quit request, wait up to 30 s, never force-kill) → save the current auth.json as Lab → write Acme’s → verify the identity Codex now reports → commit → reopen Codex.app. If verification fails, Lab’s file is restored. Codex CLI processes already running keep the account they loaded; new ones pick up Acme.
Blocked switch (5c): if Desktop is mid-task it refuses to quit; the switch stops before any credential changes.
Scope. Codex only for now. Claude Code, Antigravity and Grok store sign-ins differently, so their submenus show no launch action until an adapter supports it. Adding an account is a Settings job: sign in once through Codex, then “Save current sign-in as…”.
Also in this turn. The blue dot marks the account Codex is currently signed in as. Title and column headers removed as requested.

2dWhat changed and why
Model. Provider → Account → Window. Every row is an account; Antigravity’s two shared pools sit in the same slot. Rows sort by pressure inside a provider, so a capped account is always first.
Bars show what is left. Full bar = fresh window, empty red track = capped, text reads “62% left”, “0% left”. Warning at 25% left, critical at 10% (the 75/90 thresholds inverted). Condensing. One line per account carries every window. The countdown is the primary reset field; the absolute local date and time moves to hover (2a), the tightest window’s second line (2b), or the submenu (2c). Nine accounts fit in about 500pt.
↺ on every row. Same vocabulary everywhere: a number is reset credits available (Codex exposes this), “—” means the vendor does not expose it, “Ready” would mean the vendor reports the window already rolled. Nothing is invented.
Labels. Account label is the nickname set in Settings, otherwise the redacted email. Plan sits under it.
Status item. Unchanged: the tightest window across all accounts; tooltip and VoiceOver name the account.

1hAssumptions and reasoning
Sources. QuotaBar PRD v0.1 and the ccheney/rations implementation plan. Name shown: Rations. Providers as the plan names them: Codex, Claude, Antigravity, Grok.
Stock macOS 14. SF Pro, vibrancy, system controls, no brand color. Comfortable = accent blue (the stock ProgressView tint), warning ≥ 75% = systemOrange, critical ≥ 90% = systemRed, stale = dimmed. Monograms are two-letter and monochrome because vendor logos are off the table.
Menu bar. The PRD’s ▮▮▯ meter, filled by thirds with what is left, plus the percent left; a drained meter is drawn hollow in red. The countdown appears on the bar only when the selected window is capped (FR-2, §10.1). A small orange dot means another provider is stale or failing; a hollow ring marks a stale reading.
Rows. Bars show what is left, so a full bar is a fresh window and an empty red track is a capped one. Countdown first, then the local date and time; the countdown is what you glance at, the timestamp is what you trust. Capped rows say “Capped” in text as well as color. Unknowns are spelled out (“Usage unknown”, “Reset time unknown”, “Reset due · checking”) and never rendered as 0%.
Antigravity. Its two shared pools stay as flat rows tagged Gemini or Claude & GPT and sort by pressure with everything else; a sub-header per pool would break FR-9 sorting.
Privacy. Emails are redacted by default, so only plan names appear. Reset credits are account-scoped and shown once in the provider header.
